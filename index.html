自己紹介

佐藤 勝 / 品質保証と業務システム開発

製造業の品質保証部門で、分析業務と並行して業務システムの内製開発を進めています。 現場の測定・校正・記録の流れを理解したうえで、社内データベースを中心に パソコン向けアプリと Web 画面を企画・設計しています。

コーディングは基本的に Cursor などの AI エージェントに任せ、 自分は要件整理、仕様の判断、レビュー、テスト方針、配布・導入・保守を担当します。 本ポートフォリオの制作も同じ進め方です。 自作アプリでありがちな属人化を避けるため、定期的なリファクタリングとドキュメント整備も続け、 IT に詳しい人が追加実装や修正に入りやすい状態を意識しています。 グループ企業内の技術発表会での発表経験もあります。

  • 自分の担当: 要件整理 / 方針・設計の判断 / レビュー / 導入・保守
  • AIエージェントの担当: 実装の大部分 / リファクタ / テストコード作成の支援
  • 主な領域: 測定機器の台帳管理、分析データの保存、測定器からの自動取込

強み

技術名の列挙より先に、制作で意識している点です。

現場の仕事から設計する

校正期限、作業前点検、承認、外部校正など、品質保証の実務の流れを踏まえて画面とデータを設計します。現場に残る運用を前提にします。

AIエージェントと役割分担する

実装の多くは AI エージェントが進め、自分は課題の切り出し、仕様の判断、レビュー、導入可否の見極めを担います。速さだけでなく、現場で使える完成度を基準にします。

配って使える完成度

社内ツールでも、権限設計、専用アカウント、パスワード保護、インストーラーと自動更新まで含めます。「動く試作」ではなく「渡して使える状態」をゴールにします。

属人化しないコードと資料

定期的なリファクタリングとドキュメントを残し、IT に詳しい人が追加実装や修正に入りやすい形を保ちます。自分が作ったものでも、引き継げる状態を前提にします。

グループ企業内発表資料

品質保証の測定記録デジタル化について、グループ企業内の発表会で説明した資料です。どのような改善を行ったかを知ってもらうために掲載しています。

制作物 02 測定器連携 / 複数PC配信

1台の測定器しかない出力を、中継パソコン経由で複数の測定用パソコンへ安全に振り分けられるようにしました。

課題

工夫

設計で意識していること

01

業務ルールを一つに保つ

管理台帳では、パソコン版と Web 版が同じ業務処理を参照します。画面は違っても、判定や権限の考え方は揃えます。

02

現場へ渡し、後任も入れる状態にする

実行ファイル化、インストーラー、自動更新に加え、リファクタリングとドキュメントで属人化を抑え、IT に詳しい人が修正・追加しやすい形を残します。

03

権限と秘密情報も設計対象にする

アプリ専用のログイン、必要最小限の権限、パスワードの暗号化保存など、配ったあとのリスクも扱います。

04

実際の測定器とつながる前提で作る

無線、ケーブル通信、社内ネットワーク配信、装置通信など、実機前提で設計し、検証用の模擬環境も用意します。
